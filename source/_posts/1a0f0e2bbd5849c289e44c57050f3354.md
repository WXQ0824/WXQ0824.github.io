### 1、创建接入模板

802.1X 认证：dot1x-access-profile

```apache
dot1x-access-profile name employee
```

哑终端-AP（mac认证）：mac-access-profile

```apache
mac-access-profile name employee
```

### 2、创建Radius模板

```apache
#认证、计费服务器
radius-server template Employee                   // 服务器的配置模板主要做认证+计费
    radius-server authentication 10.1.60.2 1812   //配置服务器中的认证模块，指向10.1.60.2的服务器，其中暴露端口是1812
    radius-server accounting 10.1.60.2 1813       //配置服务器中计费模块，指向10.1.60.2的服务器，其中暴露端口是1813
    radius-server shared-key cipher Huawei@123    //服务器配置了设备验证密码，确保合法设备
#授权服务器
radius-server authorization 10.1.60.2 shared-key cipher Huawei@123 //配置服务器中的授权模块，指向10.1.60.2的服务器
```

以上两步完成了AGG至服务器的Radius服务通信，但用户端的的认证尚未指定

### 3、在aaa中创建绑定认证、计费模板，以及创建相关域并关联认证模板、计费模板和Radius服务器

有线终端的模板与域配置

```apache
aaa
   authentication-scheme Employee   //配置 Employee 的认证模板
      authentication-mode radius    //其中认证的模式使用radius认证
   accounting-scheme Employee       //配置 Employee 的计费模板
      account-mode radius           //其中计费的模式使用radius计费

domain employee                  //创建一个域，需要后面的设备接入
   authen-scheme Employee        //配置域模板中的认证方式，采用Employee的认证模板
   accouting-scheme Employee     //配置域模板中的计费方式，采用Employee的计费模板
   radius-server Employee        //由于当前两个模板都指向要用Radius完成后续步骤，但是不知道Radius是谁，所以指向我们一开始创建的Radius模板

```

无线AP的模板与域配置

```apache
aaa
   authentication-scheme ap_noauth   //配置AP认证模板
      authentication-mode none  //当前认证模式为不认证
      
domain ap_noauth  //创建一个认证域提供给AP这种哑终端不认证使用
   authentication-scheme ap_noauth  //调用当前用户设置的认证模板为ap_noauth
```

### 4、让接入用户强制进入认证模板

```apache
authen-profile name Employee  //创建一个认证的模板文件
    dot1x-access-profile employee //调用全局使能的802.1X的模板
    access-domain employee force //强制用户接入到我们设置的aaa中的employee的域
```

针对AP用户，需要强制指定其为mac认证

```apache
authen-profile name Employee  //进入相同认证模板文件
    mac-access-profile employee //调用全局使能的mac的模板
    authentication dot1x-mac-bypass //无法通过 dot1x 的设备通过 mac 认证上线
#在ap-noauthen 域中指定不认证上线的AP对应的MAC地址
domain ap_noauth mac-authen force mac-address 3458-4065-dbd0 mask ffff-ffff-ffff
```

### 5、汇聚交换机AGG的接口强制调用认证模板

在AGG与ACC1、ACC2的互联接口上，调用认证模板

```apache
interface eth-trunk 2 
    authentication-profile Employee
interface eth-trunk 3 
    authentication-profile Employee
```

### 6、在接入交换机透传认证报文

由于不支持策略联动，因此仅可使用透明传输，需要在接入层交换机ACC上设置透传

```apache
#新建一个二层透明协议dot1x
l2protocol-tunnel user-defined-protocol dot1x protocol-mac 0180-c200-0003 group-mac 0100-0000-0002 //把二层协议报文的组播目的 MAC 地址替换成为一个指定的组播 MAC 地址。
# 对用户的上行数据进行透明传输
int range GigabitEthernet 0/0/1 to GigabitEthernet 0/0/20
   l2protocol-tunnel user-defined-protocol dot1x enable //命令用来使能接口的二层协议透明传输功能
# 对服务器的回包数据同样进行透明传输
interface eth-trunk 1
   l2protocol-tunnel user-defined-protocol dot1x enable //命令用来使能接口的二层协议透明传输功能。

```

### 7、在AGG上指定vlan pool

vlan pool的相关名字需要与服务器一致，确保认证完成后能正确分配对应的vlan

```apache
[X_T1_AGG1]
vlan pool market
   vlan 11 to 15
vlan pool procure
   vlan 21 to 25
[X_T2_AGG1]
vlan pool finance
   vlan 31 to 35
vlan pool hr
   vlan 41 to 45

```

### 8、AGG下行接口修改为hybrid类型

hybrid类型接口才能实现认证

```apache
int eth-trunk 2 
   port link-type hybrid   //为了准入认证的需求，所以AGG1连接到ACC1的接口必须设置为Hybrid
   port hybrid tagged vlan 11 to 15 21 to 25 100
int eth-trunk 3
   port link-type hybrid   //为了准入认证的需求，所以AGG1连接到ACC1的接口必须设置为Hybrid
   port hybrid tagged vlan 11 to 15 21 to 25  

```
